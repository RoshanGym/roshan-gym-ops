# Roshan Gym Ops — deployment guide

This is a real, database-backed version of the Roshan Gym app: Next.js on.
Vercel, Postgres on Supabase. Follow these steps in order.

## 1. Create a Supabase project

1. Go to https://supabase.com, sign in, and click **New project**.
2. Pick any name/region/password (the password is for the Postgres superuser,
   not for your staff logins — you won't need it day to day).
3. Wait for the project to finish provisioning (~2 minutes).

## 2. Run the database schema

1. In the Supabase dashboard, open **SQL Editor**.
2. Open `supabase/schema.sql` from this project, copy all of it, paste it into
   the SQL Editor, and click **Run**.
3. This creates all the tables, seeds the pricelist, seeds your staff logins,
   and creates a private storage bucket called `attachments`.

Everyone's starting password is **roshan123** — usernames are `loraine`,
`mica`, `andre`, `francis`, `ela`, `fhe`, `ronald` (first names). Each person
should change their password after first login (top bar → Change password).

## 3. Get your Supabase keys

In the Supabase dashboard: **Project Settings → API**.

- Copy **Project URL** → this is `SUPABASE_URL`.
- Copy the **service_role** key (not the `anon` key) → this is
  `SUPABASE_SERVICE_ROLE_KEY`.

The service role key is powerful — it bypasses all database security rules.
Never put it in client-side code or commit it to a public repo. It only ever
belongs in Vercel's environment variables, where this project uses it.

## 4. Push this project to GitHub

```bash
cd roshan-gym-vercel
git init
git add .
git commit -m "Initial commit"
```

Create a new (private, if you prefer) repo on GitHub, then:

```bash
git remote add origin https://github.com/YOUR-USERNAME/YOUR-REPO.git
git branch -M main
git push -u origin main
```

## 5. Deploy to Vercel

1. Go to https://vercel.com, sign in, click **Add New → Project**.
2. Import the GitHub repo you just pushed.
3. Before clicking Deploy, open **Environment Variables** and add:
   - `SUPABASE_URL` — from step 3
   - `SUPABASE_SERVICE_ROLE_KEY` — from step 3
   - `SESSION_SECRET` — any long random string (run `openssl rand -base64 32`
     in a terminal to generate one)
4. Click **Deploy**.

That's it — Vercel gives you a URL like `roshan-gym-ops.vercel.app`. That's
your team's app.

### Alternative: deploy from your computer without GitHub

```bash
npm install -g vercel
cd roshan-gym-vercel
vercel
```

Follow the prompts, then run `vercel env add` three times to set the same
three environment variables, then `vercel --prod` to go live.

## 6. First login

Go to your Vercel URL, sign in as any of the seeded staff (e.g. username
`ronald`, password `roshan123`), and change the password immediately from
the top bar.

## What's different from the Claude.ai prototype

- **Real accounts.** Passwords are hashed with bcrypt and checked on the
  server. The browser never sees password hashes.
- **Real access control.** Every action (approve, reject, prepare payment,
  etc.) is checked against your role *on the server*, not just hidden in the
  UI. Opening browser dev tools and calling the API directly still respects
  the same rules.
- **Real file storage.** Attachments live in Supabase Storage in a private
  bucket. Files are only ever served through a signed, short-lived URL
  generated by your own API — never exposed publicly.
- **Multi-device, multi-user, permanent.** Anyone on your team can use this
  from their own phone or computer, at the same time, and the data is a real
  Postgres database with normal backup/export options through Supabase.

## What this still doesn't have (be aware)

- **No password reset via email.** If someone forgets their password, a
  Supervisor or Owner resets it for them from "Manage staff." There's no
  "forgot password" email flow — adding one would mean wiring up an email
  provider (e.g. Resend, Postmark) and is a reasonable next step if this
  grows.
- **No rate limiting on login.** Someone could try many passwords in a row
  without being locked out. Fine for a small internal team; worth adding
  (e.g. via Vercel's built-in protections or a library like `@upstash/ratelimit`)
  if this is ever exposed more broadly.
- **No automated backups configured beyond Supabase's own.** Supabase keeps
  point-in-time backups on paid tiers — check your plan's retention window.
- **Single session secret.** Rotating `SESSION_SECRET` logs everyone out at
  once (harmless, just means everyone re-enters their password).

## Local development

```bash
npm install
cp .env.example .env.local   # then fill in your real values
npm run dev
```

Visit http://localhost:3000.

## Project structure

```
app/api/            Server routes (the only thing that talks to Supabase)
lib/                 Shared server helpers (auth, db client, ID generator)
public/app.html      The app's HTML/CSS shell
public/app.js        The app's client-side logic (talks only to /api/*)
supabase/schema.sql  Database schema + seed data — run once in Supabase
```
